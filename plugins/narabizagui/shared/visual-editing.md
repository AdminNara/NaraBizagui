# Correcciones visuales con menos reprocesos

Contrato `visual-quality-v1`, web 0.9.3 / plugin 0.8.1. Comprueba las capacidades efectivamente cargadas, incluida la operación en el esquema de la herramienta y en `capabilities.batchOperations`; el nombre del contrato no acredita todas las ampliaciones posteriores. Una instalación no actualiza un chat o una pestaña anteriores. No recargues ni sustituyas el archivo del usuario para obtenerlas.

Para un ajuste pequeño: una lectura suficiente del conjunto y sus obstáculos, un plan coherente, un `edit_batch` compatible, revisión incremental incluida y una confirmación visual. Reutiliza sesión, revisión confirmada, instrucciones y contrato. Evita llamadas por objeto, tantear coordenadas, exportaciones repetidas y guardados manuales si el autoguardado ya está activo. El bloque ya prevalida; no dupliques `dryRun` salvo incertidumbre real o propuesta que el usuario quiera revisar.

- `resize` admite tareas, CallActivity y subprocesos contraídos desde 100×80 mediante reglas y comandos nativos. `fit_text` reserva iconos/marcadores y busca dimensiones suficientes con la fuente elegida (16 px por defecto); no reduce fuentes para hacerlas caber ni mueve vecinos. Si no hay espacio, devuelve `TEXT_FIT_NO_SPACE`: planifica el conjunto, sin reducir texto ni significado. Revisa `textLayout.fits` y `contentPreserved` sobre texto SVG real, también en PNG.
- `route_orthogonal` recibe `sourceSide`/`targetSide` (`auto`, `top`, `right`, `bottom`, `left`), offsets 0.05–0.95 y margen 2–40. Conserva lados persistidos cuando se omiten. Minimiza longitud y codos en el corredor local, considerando figuras y etiquetas. Una salida a un documento debajo/derecha suele ser una L: no investigues todo el diagrama para resolverla. Un espacio bloqueado se rechaza; no lo resuelvas con una vuelta por todo el perímetro. Revisa rodeos, tramos cortos y cruces, incluidas asociaciones y hojas auxiliares.
- Mover un segmento conserva el lado. Reconectar cambia el extremo elegido. Recalcular reemplaza el recorrido de esa conexión; no replantea líneas manuales ajenas. `route` conserva puntos explícitos y registra lados. No se afirma que una auditoría sin cruces produzca la mejor disposición.
- `share_connection` (servidor 0.8.1 y web 0.9.3) recibe `elementId`, `withConnectionId`, `x`, `y` y `end:target|source`. Comparte un tramo de llegada con destino común o de salida con origen común, conservando IDs, extremos y selección independiente. La unión es visual; no crea un nodo ni una sincronización BPMN implícita. El comando rechaza un cambio silencioso de destino/origen y ciclos entre referencias visuales. Para dos ramas que requieren sincronización usa compuertas explícitas. Conexiones sin destino no están soportadas como secuencias BPMN válidas: no simules un borrador con nodos inventados. En UI arrastra el extremo a otra línea; el selector de conexiones coincidentes permite elegir cada una.
- `style`, `delete`, `fit_text`, `route_orthogonal` y `compact_container` se agrupan con etiquetas, geometría y propiedades. `delete` rechaza hijos/conexiones salvo `cascade:true` expresamente previsto. `compact_container` recorta solo margen derecho/inferior de un participante, respetando figuras, etapas, etiquetas y rutas interiores; con carriles conserva su altura. No compacta automáticamente todo un flujo ni mueve elementos manuales.
- Un documento requiere `properties.values.documentFormat` (`Documento`, `Excel`, `Word`, `Manual`, `Datos`) y `documentUse` (`Referencia`, `Entrada`, `Salida`, `Entrada/Salida`); cambiar el nombre a Excel no cambia el icono. Usa DataState nativo, conservando ID y asociaciones. Hojas/rangos del mismo libro se representan como usos del mismo documento; no inventes archivos ni dupliques libros sin una necesidad explícita.

Los flujos cortos y hojas de detalle no llevan etapas por rutina. Usa solo las que aclaren el proceso. Conserva el orden y los recorridos corregidos manualmente, responsables, entradas/salidas y condiciones; compacta únicamente el conjunto afectado. No añadas leyendas automáticas, notas de revisión, pendientes ni referencias a informes dentro del proceso. Los títulos describen el negocio; documentos operativos reales se conservan. Pendientes, dudas y aprobación se tratan fuera del lienzo. Reutiliza un documento real con varias asociaciones cuando sea legible, hasta cinco si no se cruzan, sin rótulos artificiales como “Mismo libro Excel”. Un rol de una empresa aliada se identifica como externo sin atribuirle pertenencia a la organización modelada.

La respuesta conserva claves anteriores y añade `ok`, `outcome`, sesión explícita y `responseSchema`. Importa `parseToolResult`, `confirmedState` y `recoveryDecision` de `result.mjs`, o usa `snapshot-cli.mjs normalize/state`. Un preview, rechazo o error no es estado editable. `RESULT_UNKNOWN` requiere una reconciliación de lectura antes de repetir; conflicto exige conservar cambios manuales. Una espera/relectura acotada; si persiste, detener mutaciones. Mantén `expectedRevision`, UUID, idempotencia y recuperación.

`validate.elementIds` limita `quality` a figuras y conexiones incidentes; el diagnóstico BPMN sigue siendo de la hoja. Calidad visual y validez BPMN son resultados distintos; ninguna aprueba el negocio. Una lectura filtrada o sin texto renderizado no acredita revisión completa. Para medir agilidad compara el mismo conjunto, registra llamadas, reintentos y tiempo de preparación a confirmación. `firstVisibleMs` y transporte no miden razonamiento ni el turno completo.
